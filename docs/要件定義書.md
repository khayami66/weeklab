## 2. プロジェクト概要

### 2.1 背景
小学校の理科専科教員は、毎週の週案作成にあたり、年間指導計画・時間割・クラス別進度・単元内容などを複数の情報源から手作業で突合している。特に理科専科は複数クラス（MVP想定では7クラス）を掛け持ちするため、クラスごとに進度が異なり、週案作成の負担が大きい。また、作成した週案は管理職に提出する必要があり、所定様式での印刷が求められる。

### 2.2 目的
以下の3点を達成する：
1. 週案作成の時間を大幅に短縮する
2. 進度管理の正確性を担保する
3. 管理職提出用に印刷可能な週案を自動生成する

### 2.3 対象範囲

| 層 | MVP | 将来 |
|---|---|---|
| 学校 | 松戸市立梨香台小学校 | 啓林館採用校（松戸市内→全国） |
| 教科 | 理科 | 国算社 他 |
| 学年 | 3年・4年 | 全学年 |
| 教科書 | 啓林館 | 東京書籍・大日本図書・光村 等 |
| ユーザー | 理科専科教員（本人） | 担任・他専科教員 |

### 2.4 配信・運用形態
- **Webアプリケーション**として Vercel 上にデプロイ
- URL を知る個人のみアクセス可能（MVPは限定URL）
- 利用端末：**MVP は自宅PC（Chrome / Edge）を動作保証対象**。iPad・スマホは閲覧可能だが動作保証対象外（将来ユーザー拡大時に対応）
- **児童の氏名は一切扱わない。学年・クラス・出席番号のみで扱う**（v1.6 で成績処理を統合したため明確化）
  - 扱う：学年・クラス・出席番号、観点別の得点、A/B/C 判定
  - 扱わない：氏名・ふりがな・生年月日・児童ID、所見文、行動の記録
  - 出席番号と氏名の対応は教員の手元の名簿にのみ存在し、本システムには入らない
  - この方針により、成績処理を統合しても限定URL運用の前提は維持される

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| カリキュラムパック | `publisher × subject × grade` 単位の共有データ（年間指導計画＋単元別授業内容）。複数校で再利用できる。 |
| 教員個人設定 | 学校名・年度・時間割・進度など、ユーザー固有のデータ |
| 年度 | 日本の学校年度（4月〜翌3月）。例：「2026年度」は 2026年4月〜2027年3月 |
| 第n週 | 始業式のある週を第1週とし、以降機械的に加算 |
| 本時 | ある単元内でのn時間目（例：「生き物をさがそう」の1/4時間目） |
| 週案 | 1週間の授業予定表。本システムの主要出力物 |
| Y案 | 理科専科独自1枚様式（全クラスを1枚に集約、管理職合意済み） |
| アーカイブ | 年度切替時に凍結保存された過去年度データ（読み取り専用） |
| 週先頭コマ確定 | 各クラスの今週最初のコマの単元・本時をユーザーが確定する操作。以降のコマは LessonMaster 順で自動表示 |
| 進度ヘルスチェック | 期待累計時数（年間配当×進行率）と実累計の差から進度ずれを判定する機能 |
| 月次集計 | 月別クラス×単元の実施時数マトリクス。教育委員会報告用 |
| 観点 | 評価の観点。本システムが扱うのは「知識・技能」「思考・判断・表現」の2つ。「主体的に学習に取り組む態度」はペーパーテストで測れないため対象外 |
| 通算得点率 | 集計期間内の全単元テストについて、観点ごとの「合計得点 ÷ 合計満点」。学期の評定はこの値に閾値を当てて決める |
| 観点の偏り | 知識・技能と思考・判断・表現の得点率の差。指導改善の手がかりとして提示する |

## 4. システム概要

### 4.1 システム構成
```
[ブラウザ (PC/iPad/スマホ)]
       │ HTTPS
       ▼
[Vercel (Next.js)]
  ├── 静的アセット
  ├── App Router 画面
  └── TS定数として格納されたカリキュラムパック
       │
       ▼（クライアント側）
[localStorage]
  ├── 教員個人設定・進度・例外・メモ・アーカイブ
  └── 成績（テストマスタ・評定閾値・テスト得点）
```

- サーバー側での永続化はMVPでは行わない
- 全データはブラウザの localStorage に保存
- バックアップは JSON エクスポート機能で対応

### 4.2 利用イメージ
1. 教員が朝、ホーム画面で今日の理科予定を確認
2. 週末に週案画面で翌週の予定を確認・メモ追記
3. 印刷画面から週案を A4横で出力 → 管理職に提出
4. 授業実施後、進度管理画面で完了時数を更新
5. 行事で時間割が変わる週は、時間割画面で例外を入力
6. 単元テストを採点したら、成績画面でクラス単位に得点を入力
7. 学期末に集計期間を指定して観点別 A/B/C を算出 → 校務支援システムへ転記
8. 年度末に年度切り替えを実行 → 新年度は進度リセット、過去年度はアーカイブ

### 5.2 機能詳細

#### F01 カリキュラムパック管理
- `publisher × subject × grade` をキーとする `CurriculumPack`
- 年間指導計画（`AnnualPlan`）と単元別授業内容（`LessonMaster`）を保持
- データはTS定数としてビルド時に組み込み
- `CurriculumPack.year` は発行年度を保持（MVP初期値 `2024`：令和5年検定済・令和6年発行）
- 教科書改訂時は新パックを追加、旧パックは破棄

#### F02 教員個人設定（初期設定を1画面に集約）
`/settings` 画面で以下をすべて設定・編集：
- 学校名、教員名、**年度**、**始業式日**
- **教員タイプ（`teacher_type`）**：`specialist`（専科、MVP）/ `homeroom`（担任、将来対応）
- **学年構成（`grade_configs`）**：`{ grade, class_count, pack_id }` の配列。担当学年・クラス数・使用パックを一元管理
- **基本時間割**（F03）：月〜土 × 時限のマトリクスで各コマを設定
- 「使用中パック一覧」は `grade_configs` から派生（Single Source of Truth）
- 始業式日は第1週の起点として週番号算出に使用
- クラス（`ClassProgress`）は `grade_configs` から自動生成

#### F03 基本時間割（F02 に統合）
- 月〜土 × 時限（1〜6限）のマトリクス
- 専科教員（MVP）：各コマで**クラスを選択**（`grade_configs` から派生するクラスコード一覧）
- 担任教員（将来）：各コマで**教科を選択**（`teacher_type === "homeroom"` の UI 分岐で対応）
- 初期値は空（新規ユーザーがゼロから入力）、編集は設定画面でいつでも可能
- **時刻は扱わない**：本システムは進度・時数管理が目的

#### F04 週内例外（週案画面に統合）
- `/weekly` 画面で該当週のコンテキスト内に編集UI
- `TimetableOverride` として日付・時限単位で保持
- 変更タイプ：`cancel`（休講）／`replace`（差し替え）／`add`（追加、土曜授業等）
  - **`replace` は画面からの入口を廃止**（2026-09-07）。枠を固定したので
    「×で消して同じ枠の＋で別クラスを追加」で代替できる。データ処理は残す
- **個別コマの休講は理由を聞かない**（即実行）。理由は1日まるごとの休講でのみ入力する。
  1コマずつ入力させると、行事の週で週案作成がかえって遅くなるため
- 週案生成時にベース時間割とマージ

#### F05 進度管理
- クラスごとに `current_unit_name` と `completed_hours`、`total_completed_hours`
- 完了時数が当該単元の全時数を超えたら次単元へ繰り上げ
- 年度開始からの累計時数も保持（印刷の「実施累計」に使用）

#### F06 週案自動生成
- `generateWeeklyPlan(weekStart, setting, timetable, overrides, progress, packs, firstLessonConfirms?)`
- 月〜土 の6日分を生成
- 各クラスの週先頭コマはユーザー確定値があればそれを採用、なければ `ClassProgress` から推定
- 2コマ目以降：先頭コマの次から `LessonMaster` を順に割り当て、単元完了時は年間計画順で次単元へ

#### F07 週案表示
- 上部：第n週 / 期間 / クラス別集計（週実施・実施累計）・進度ヘルスバッジ
- **週先頭コマの指定**：各クラスの**その週最初のコマのカード上**で単元・本時を選ぶ
  （2026-09-07 変更。以前は画面上部の独立セクションだったが、どのコマの話か分かりにくかった）
  - 変更は即時保存。「開始 推定／指定済み」のバッジで状態が分かる
- 中段：曜日ごとのコマ一覧（先頭コマ以降は自動表示）
- 各コマ：時限・クラス・単元・本時・内容・メモ
- メモは inline 編集（blur で localStorage 保存）

#### F08 今日の授業一覧
- 本日の時限順カード表示
- クリックで週案画面へ

#### F09 週案印刷
- A4横、`@media print` 対応
- Y案：クラスコード＋単元名＋授業内容の3行で1セル
- 下段：クラス別の週実施／実施累計
- 検印欄は空欄（手書き）
- 週先頭コマ未確定時も `ClassProgress` 推定値で無警告印刷（画面上のみ `slate-400` で「未確定」バッジ表示、印刷面には出さない）

#### F10 月次集計
- `/monthly` 画面で月選択 → クラス×単元マトリクス表示
- `computeMonthSummary(year, month, ...)` で算出
- 月曜日が属する月で集計（週をまたぐ週は月曜日の月）
- 印刷対応（`/print/monthly`）、教育委員会提出用

#### F11 進度ヘルスチェック
- `checkProgressHealth(progress, annualPlan, currentWeekNo, totalWeeks)`
- 期待累計 = 年間配当時数 × (現在週 / 全週数)
- 差 ±3時間未満：ok（緑）、±3〜5時間：warn（amber）、±5時間以上：alert（rose）
- ホーム・週案・進度画面にバッジ表示

#### F12 授業案の編集・マスタ確認

**当初は「閲覧のみ」の予定だったが、編集機能に格上げした（v1.8）。**
`LessonMaster` が全件空のままで、週案の授業内容欄が「(未作成)」しか出せず、
**週案システムの中心が機能していなかった**ため。

- `/master` で 学年 → 単元 を選ぶと、**年間指導計画の配当時数ぶんの行**が出る
- 各行に「本時のタイトル」「授業内容（1〜2行）」を書く。週案の各コマに表示・印刷される
- 単元ボタンに記入の進み具合（`3/8 記入`）を出し、埋まったら緑にする

**2層構造（設計の要）**

| 層 | 型 | 位置づけ |
|---|---|---|
| パック層 | `LessonMaster` | 教科書ベースの標準案。**全国で共有できる資産** |
| ユーザー層 | **`LessonPlan`** | その学校・その教員が実際にやる授業案。**標準案を上書きする** |

基本時間割に対する `TimetableOverride`、教科書に対する `TestMaster` と同じ形。
**地域性・手元の教材・「教科書通りだとつまらない」への対応はすべてユーザー層に書けばよく、
共有資産であるパック層は汚れない。**

- 合成は `mergeLessonPlans()`（純粋関数）。ユーザー案が常に優先
- **タイトルも内容も空の授業案はパック層を隠さない**（「未入力」と「空にした」の区別）
- 既存の週案生成ロジック（`resolveCurrentLesson` / `generateWeeklyPlan`）は**無変更**。
  合成後の `LessonMaster[]` をそのまま渡している
- `LessonPlan` は `total_hours` を持たない。単元の時数は `AnnualPlan.allocated_hours` が正本

**AI との壁打ちについて**：1時間ごとの内容は AI との壁打ちで作ることを想定しているが、
**AI 機能はアプリに組み込まない**（v1.8 時点）。すでに外部の AI で成立している作業であり、
APIキー・費用・特定AIへの固定を持ち込む必要がない。当面は**書いた結果を貼り付ける**運用とする。

#### F13 年度切り替え
- 設定画面からモーダルで実行
- 新年度番号、新しい始業式日を入力
- 時間割・パック選択の引き継ぎ可否を選択
- 現年度データを `ArchivedWeek[]` に変換して保存
- 新年度は進度リセット
- **週先頭コマ確定値（`first_lesson_confirms`）は新年度に引き継がない**（年度プレフィックス付きキーで自然分離、新年度は空から確定していく）

#### F14 アーカイブ閲覧
- 年度一覧から選択 → 週一覧 → 週案詳細
- 完全に読み取り専用
- 印刷も可能（当時の単元名・内容がそのまま保存されている）

#### F15 JSONエクスポート/インポート
- エクスポート：`FullSnapshot` 形式で全年度を1ファイル化、ダウンロード（`weeklab-backup-YYYYMMDD-HHmm.json`）
- インポート：ファイル選択 → **中身の件数を表示して**確認 → 全上書き → リロード
- **対象は全データ**：設定・時間割・例外・進度・メモ・週先頭コマ確定・確定済み週・
  **成績3種（テストマスタ・評定閾値・テスト得点）**・**授業案（`LessonPlan`）**・アーカイブ
- **永続化キーを増やしたら、必ずエクスポート/インポートの両方に追加すること。**
  型に optional で足しただけでは型検査が通ってしまい、
  「保存はできるがバックアップから復元できない」データが静かに生まれる。
  `lib/datasource/exportImport.test.ts` の往復テストが検出器になっている
- 本機能は**成績の移行入力より前に必要**だったため、F13/F14 より先に実装した（2026-09-04）

#### F16 LINE通知用関数
- `getLessonsForDate(date): WeeklyPlan[]`
- `formatLessonsForLine(lessons, date): string`
- MVPは関数のみ公開、送信基盤は将来実装

#### F17〜F20 成績処理（詳細は `grading_design.md`）

成績処理は当初「別システムとして切り分け、将来API連携」としていたが、
**「テスト結果がなぜそうなったのか」の分析には週案・進度・時数との突合が不可欠**であるため、
Weeklab に統合する方針に転換した（v1.6）。

#### F17 評定閾値・テストマスタ管理
- `GradeThreshold`：観点ごとの A/B 下限。**初期値 A=90% / B=60%。固定値ではなく設定画面で変更可**
  - 学期評定タブで A/B/C の分布を確認してから調整できるようにする（計測先行）
- `TestMaster`：業者テストの定義（テスト名・観点別満点）。ユーザーがローカル登録
  - **単元との紐づけは任意。**「1学期のまとめ」のように複数単元にまたがるテストがあるため。
    無理に近い単元を選ばせると、将来の「配当時数 × 単元ごとの結果」の突合で誤った対応づけが生まれる
  - **観点の出題がないテストは満点 0** で登録する。入力欄が作られず、通算の分子・分母からも外れる
    （「0点を取った」とは区別される）
- いずれも `/settings` に追加するセクションで編集
- **名簿（在籍人数）の設定は持たない。** 全クラス一律で出席番号 1〜35 の行を用意する
  （小学校の学級編制標準が35人のため）。転出入で設定を触る必要をなくすのが狙い。
  在籍していない番号は「全テスト未受験」として自動的に集計から外れる

#### F18 テスト得点入力
- テスト×クラスを選び、出席番号順に「知識・技能」「思考・判断・表現」の合計点を入力
- **未受験は空欄（`null`）**。0点と明確に区別し、通算の分子・分母から除外する
- 満点超過はその場で警告

#### F19 学期評定算出
- 集計期間を日付範囲で指定（学期制の違いに依存しないため、設定には持たない）
- 観点ごとに `合計得点 ÷ 合計満点` を通算し、閾値を当てて A/B/C を判定
- 単元ごとのA/B/Cを多数決する方式は採らない（境界で判定が不安定になるため）
- クラスごとに A/B/C の分布を表示（閾値調整の根拠になる）
- **受験テスト数を並べて表示する。**転入等で受験数が少ない児童は、少ないテストで評定が
  決まるため、そのクラスの最多受験数を下回る場合に印を出す
- **得点率は小数第1位まで表示する。**整数に丸めると、真の値 89.6% が「90%」と表示されて
  評定は B、という食い違いが起きる（判定は丸めない得点率に閾値を当てているため）
- 校務支援システムへの入力元として使う

#### F20 観点の偏り分析
- クラス単位：知識・技能と思考・判断・表現の平均得点率の差
- 児童単位：差の大きい児童を抽出
- 判定は `ProgressHealth` と同じ ok/warn/alert の3段階（初期案 10pt / 20pt）

## 6. 非機能要件

### 6.1 UI/UX
- 日本語UI
- 学校現場に馴染む平易な表現
- 青・グレー系の落ち着いた配色
- タップ領域 ≥ 44px（将来の iPad 対応を見越した設計）
- **MVP の動作保証対象は PC（Chrome / Edge）のみ**。iPad・モバイルはレスポンシブ設計で閲覧可能にとどめる

### 6.2 パフォーマンス
- ローカル計算のみのため即応（画面遷移 < 500ms）
- 1週間の週案生成 < 100ms
- localStorage 読み書き < 50ms

**実測（2026-09-04、本番ビルド＋実施機。詳細は `開発ログ.md`）**

最も重い画面は成績入力（35行 × 最大12列 = 420個の制御された入力）。
ヘッドレスブラウザで人の打鍵速度（150〜250ms/打鍵）を再現して計測した。

| 条件 | 打鍵→画面に出るまで（中央値） |
|---|---|
| **実施機（等速）** | **32 ms** |
| CPU 2倍遅い機械を想定 | 86 ms |
| CPU 4倍遅い機械を想定 | 193 ms |

- 実施機では体感できる遅延はない（105打鍵を通して最悪 52ms）
- **入力数を5倍にしてもレイテンシは1.4倍にしかならない**（コストの大半はセル数に
  よらない固定費）。したがって将来重くなった場合でも、**セル単位のメモ化は打ち手にならない**
- 計測の注意：打鍵間隔を人より速くすると待ち行列ができ、**存在しない「性能の崖」が観測される**

### 6.3 保守性
- ロジック層（`lib/`）とUI層（`app/` `components/`）を分離
- 型定義は `types/index.ts` に集約
- データソース抽象層（`DataSource`）で永続化層を差し替え可能
- CSV ⇄ TS定数の相互変換を容易にするフラット構造

### 6.4 セキュリティ
- **児童の氏名は扱わない**（学年・クラス・出席番号のみ）
- 成績データを扱うが氏名を持たないため、単体では個人を特定できない
- 限定URL運用は維持可能。ただし成績を扱う以上、URLの共有は行わない
- 将来、複数教員が使う段階になれば認証を別途設計する（氏名を持たない設計でも、他教員の担当クラスの成績は見えるべきでないため）

### 6.5 可用性
- Vercel 無料枠で運用
- データは localStorage（クライアント側）
- JSONエクスポートでバックアップ可能
- サーバー障害時も過去データは閲覧可能（ブラウザキャッシュ）

### 6.6 運用性
- 年度切り替えはユーザー自身が設定画面から実行
- マスタ（カリキュラムパック）更新はコード変更＋再デプロイ
- 将来、CSVインポートや管理画面を追加予定

## 7. データ要件

### 7.1 データ構造の概要
詳細は `data_model.md` を参照。

**主要な型：**
- パック層：`CurriculumPack` / `AnnualPlan` / `LessonMaster`
- 個人設定層：`TeacherSetting` / `TeacherType` / `GradeConfig` / `Timetable` / `TimetableOverride` / `ClassProgress` / `FirstLessonConfirm` / **`LessonPlan`**
- 成績層：`ViewPoint` / `GradeLevel` / `TestMaster` / `TestScore` / `TestResult` / `GradeThreshold`（名簿の型は持たない）
- 派生：`WeeklyPlan` / `WeekSummary` / `ClassTally` / `ProgressHealth` / `MonthlySummary` / `MonthlyClassTally` / `ViewPointResult` / `StudentGrade` / `ViewpointBalance`
- アーカイブ：`ArchivedWeek` / `ArchiveMetadata` / `FullSnapshot`

### 7.2 永続化
- マスタ：TS定数（ビルド時固定）
- 教員個人設定：localStorage（年度プレフィックス付きキー）
- バックアップ：JSONファイル（ユーザーのダウンロードフォルダ）

### 7.3 データ量見積
- 1年度あたり：週案約40週 × 6日 × 最大6コマ = 約1440レコード
- 進度：7クラス × 数値フィールド = ごく少量
- localStorage 上限（通常5MB）には余裕で収まる

## 9. 制約事項

### 9.1 技術制約
- Next.js（App Router）＋ TypeScript を使用
- ブラウザ環境（localStorage依存）
- MVPではサーバー側ストレージなし

### 9.2 運用制約
- 学校PCには導入しない（セキュリティ制約）
- 自宅PCからの利用が基本
- 端末間同期はJSONエクスポートで手動対応

### 9.3 スコープ制約
- 理科以外は対象外（MVP）
- **成績処理はテストで測れる2観点のみ**。「主体的に学習に取り組む態度」は対象外
- **設問別の分析は行わない**（入力は観点ごとの合計点のみ）。分かるのは観点の偏りまで
- 追試・再テストは扱わない（1テスト1回）
- **テストの発行元（業者名）は記録しない。**教科書会社とテスト発行会社は別であり
  （2026年度：教科書＝啓林館／テスト＝教育同人社）、記録する価値はあると判断したが
  優先度が低いため見送った。`TestMaster.pack_id` は**単元の出どころ（教科書）**を指すもので、
  テストの発行元ではない。再検討は他教科対応時または年度切替の実装時（`grading_design.md` §9-6/#7）
- 祝日・長期休業は未対応（画面上は平日扱い、手動で無視）
- 学校行事は `TimetableOverride` に手動入力
- **時刻（`start_time`/`end_time`）は扱わない**：本システムの目的は進度ずれとコマ数消化の管理であり、時間帯情報は不要
