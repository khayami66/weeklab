# コマ内容の差し替え（テスト・差し込み）設計プラン

- 版：1.0（2026-09-08）
- 状態：**実装中**（2026-09-08 承認）
- 関連：`要件定義書.md` F04/F07 ／ `timetable-override-plan.md`（コマの有無の変更）／
  `grading_design.md` §9-5（週案と成績の突合）／`data_model.md` §7（永続化キー）

## 1. なぜ要るか

本人の指摘（2026-09-07）：

> 単元が終わった次の時間はテストを実施しています。
> 現在の設計では、１単元が終わるとテストを挟まずに次単元に進むと思うのですが、合っていますか？

**合っている。** 年間指導計画にテストの時間は1つも入っていない。

| 学年 | 単元数 | 配当時数 | 標準時数 | 予備 |
|---|---|---|---|---|
| 3年 | 18 | 80 | 90 | 10時間 |
| 4年 | 21 | 94 | 105 | 11時間 |

啓林館の配当時数は授業ぶんだけで、実際のテストはこの予備時数で行われている。
システムはそれを知らないため、**単元の最終時間の翌コマから次の単元が始まってしまう。**

いま本人が指定できるのは「週の先頭コマの単元・本時」だけ（`FirstLessonConfirm`）。
2コマ目以降は進度からの自動計算で、**途中のコマには手が出せない。**

## 2. 何を作るか

**どのコマも押せば「このコマで何をするか」を決められるようにする。**

- 単元・本時を指定する（＝単元途中への差し込み）
- テストにする（テストマスタから選ぶ。未選択も可）
- もとに戻す（自動計算に任せる）

テスト専用の機能にはしない。差し込みもテストも「そのコマの中身を上書きする」という
**同じ1つの仕組み**で、入り口も1つにする。

## 3. 確定した方針（本人決定・2026-09-08）

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | テストの入れ方 | **週案画面でそのコマを押して変える**（年間計画に組み込まない） | 授業は計画どおりに進まない。テストをやる週は、実際に単元が終わってみないと決まらない |
| 2 | どのテストかを記録するか | **テストマスタから選ぶ（未選択も可）** | 登録済みのテストと同じものを指せば「いつやったか」が残り、§9-5 の突合ができる。未選択を許すので手軽さも残る |
| 3 | 差し込んだ単元が「未実施」のまま残る点 | **承知のうえで進める** | テストの挿入には限界がかからない（テストは年間計画の単元ではない）。差し込みは1〜2時間の用途に限り、先に動くものを得る |

### 3-1. 先頭コマと、コマの差し替えは別物

混同すると事故になるので明記する。**先頭コマは「1時間だけ変える」道具ではない。**

| 道具 | 意味 | 影響範囲 |
|---|---|---|
| 週の先頭コマ（`FirstLessonConfirm`） | 「このクラスは今ここにいる」と現在地を宣言する | **その週の以降すべてと、確定後の進度** |
| コマの差し替え（本件） | 「このコマだけ別のことをする」 | **そのコマ1つだけ。進度は動かない** |

例：とじこめた空気や水 3/6 の途中に秋の生き物を1時間差し込むとき、
**翌週の先頭コマで「秋の生き物 2時間目」を選んではいけない。**
選ぶとクラスごと秋の生き物に乗り換わり、その週の残りも秋の生き物になり、
**とじこめた空気や水の残り時間は二度と戻ってこない**（`lib/weeklyPlan.ts` の
`vs.unit_name = c.unit_name; vs.completed_hours = c.lesson_no - 1`）。

正しくは**何もしない**。差し替えたコマは進度を進めないので、
次のコマは自動でとじこめた空気や水の続きに戻る。
秋の生き物を2時間目もやるなら、そのコマも同じように差し替えで指定する。

## 4. 進度の扱い（ここが要）

**差し替えたコマは、単元の残り時間を消費しない。**

「とじこめた空気や水 6時間」の5コマ目をテストにしたとき、それを5時間目として数えると
**授業が1時間足りなくなる。** 一方で、そのコマは実際に授業時間として実施しているので、
**週実施・月実施・実施累計には数える。**

| | 単元内の時数（`completed_hours`） | 年間の実施累計（`total_completed_hours`） |
|---|---|---|
| 通常の授業 | +1 | +1 |
| **テスト** | **+0** | **+1** |
| **差し込んだ別単元** | **+0** | **+1** |

差し込んだ別単元でその単元の進度を進めないのは、`ClassProgress` が
**クラスごとに1つの単元しか持たない**ため。複数単元を並行して数えるのは
「単元の入れ替え」（別課題）の領域で、ここでは扱わない。

## 5. データ設計

新しい配列を1つ追加する。既存の `TimetableOverride`（コマの**有無**を変える）とは軸が違う
（こちらはコマの**中身**を変える）ので、混ぜない。

```ts
/** そのコマで何をするか。既定は進度からの自動計算（＝レコードなし） */
export type SlotPlanKind = "test" | "lesson";

export interface SlotPlanOverride {
  date: string;        // "YYYY-MM-DD"
  period: number;
  class_code: string;
  kind: SlotPlanKind;
  /** kind="test" のとき。テストマスタの test_id。未選択なら "" */
  test_id: string;
  /** kind="lesson" のとき。差し込む単元名と本時 */
  unit_name: string;
  lesson_no: number;
  memo: string;
}
```

- 永続化キー：`weeklab.{year}.slot_plan_v1`
- 主キー：`date` + `period` + `class_code`（1コマ1件）

`WeeklyPlan` に判別用の項目を足す（既定は通常授業なので、既存の呼び出しは壊れない）。

```ts
kind: "lesson" | "test";   // 既定 "lesson"
test_id: string;           // テストのとき。未選択なら ""
is_plan_override: boolean; // 自分で決めたコマか（画面と紙で印を出す）
```

## 6. 変更するところ

| 層 | ファイル | 変更 |
|---|---|---|
| 型 | `types/index.ts` | `SlotPlanOverride` 追加、`WeeklyPlan` に3項目 |
| 保存 | `lib/store/localStore.ts` / `localDataSource.ts` | `slot_plan_v1` の読み書き。**エクスポート／インポートに必ず足す** |
| ロジック | `lib/weeklyPlan.ts` | `generateWeeklyPlan` に `slotPlans` を渡す。差し替えコマは仮進度の `completed_hours` を進めない |
| ロジック | `lib/progress.ts` | `advanceTotalOnly()` を追加（累計だけ +1） |
| 確定 | `app/weekly/page.tsx` | コマ数ではなく**種別ごとに数えて**進度を進める |
| UI | `components/SlotPlanPicker.tsx`（新規） | 単元・本時／テスト／戻す を選ぶパネル |
| UI | `components/WeeklyGrid.tsx` / `LessonCard.tsx` | どのコマも押せるようにする。先頭コマの青は「週の始まり」の意味で残す |
| 印刷 | `components/PrintWeeklySheet.tsx` | テストのコマを「テスト」と分かる形で刷る |

### 忘れてはいけないこと

**永続化キーを増やしたら `exportAll` / `importAll` に必ず足す。**
`importAll` は全キーを消してから書き戻すので、足し忘れると
**復元でそのデータだけ消える。** 往復テスト（`exportImport.test.ts`）の
`seedEverything()` にも `slot_plan` を足し、抜けたら落ちることを確認する
（`pitfalls/2026-09-04-new-persisted-key-not-added-to-export-silently-breaks-restore.md`）。

## 7. 画面の形

いま先頭コマだけがクリックで単元ピッカーを開く。これを**全コマに広げる**。
入り口が1つ増えるのではなく、既存の入り口が一般化されるだけなので、
カードは縦に伸びない（本プロジェクトの方針：情報は線から面へ移すか、消す）。

```
┌──────────────┐
│ ×         3-1 │   ← 押すと下にパネルが開く
│ とじこめた空気や水 5/6│
│ 空気の力で玉を飛ばそう │
│ 筒に玉を2つ入れ…    │
└──────────────┘
   ↓ 押す
┌──────────────────────────┐
│ このコマで何をしますか                │
│ ( ) 自動（とじこめた空気や水 5/6）      │
│ ( ) テスト  [とじこめた空気や水 ▾]      │
│ ( ) 単元を指定 [単元 ▾] [本時 ▾]       │
│                    [決定] [閉じる]  │
└──────────────────────────┘
```

テストのカードは色で区別する（高さを増やさないため、バッジではなく面で示す）。

## 8. 受入条件

- [ ] コマを押すとパネルが開き、テストに変えられる
- [ ] テストマスタから選べる／未選択でも「テスト」として入る
- [ ] テストのコマは**単元の時数を消費しない**（次のコマが同じ本時から続く）
- [ ] テストのコマも**週実施・月実施・実施累計には数える**
- [ ] 「今週を実施済みに確定」でテストぶんは累計だけ進む
- [ ] リロードしても残る
- [ ] **バックアップ→復元でテストの記録が消えない**（往復テストで検出）
- [ ] 印刷でテストのコマがそれと分かる
- [ ] 全36枠が埋まった週でも A4縦1枚に収まる

## 9. やらないこと（別課題）

- **年間指導計画そのものの並べ替え**（単元の順番を恒久的に入れ替える）。
  `ClassProgress` が単元を1つしか持たない構造に関わるため、別途壁打ちする。
  **既知の限界：差し込みを何時間積んでも、その単元は「未実施」のまま残る。**
  年間計画の順番が来たら、もう一度出てくる。1〜2時間の差し込みなら実害は小さいが、
  単元を丸ごと前倒しする用途には足りない。
- コマごとの自由メモ（`useLessonMemo`）。本件とは別の欄なので、必要になったら実装する。
